## Versions

EraUma已于2024/10/24发布第一个正式发布版本v1.0（kuuga），感谢各位玩家一直以来的支持与鼓励。

EraUma的版本号是一串小数部分最多三位的正有理数，在前面的数位都不变的情况下，从千分位开始从小到大的数位的改动将可能包含以下内容的变化：

* 千分位（例：1.000→1.001）
  * 口上内容调整
  * bug修复
  * 包括比赛机制在内的数值平衡
  * _不需要重新开档_
  * _不存在游戏系统变化带来的存档转换_
  * _可使用引擎的最小更新功能_
* 百分位（例：1.00/1.001→1.01）
  * 其间所有版本的改动内容
  * +可能的新角色
  * +可能的新头像和立绘（一般跟随新角色）
  * +可能的新调教立绘和背景
  * +可能的res文件夹的其他改动
  * _不需要重新开档_
  * _不存在游戏系统变化带来的存档转换_
  * _无法通过最小更新功能更新所有（主要是指res文件夹的）改动_
* 十分位（例：1.0/1.01/1.001→1.1）
  * 其间所有版本的改动内容
  * +可能的新口上或口上加笔（招募/日常/育成/爱慕/地下室/调教）
  * +可能的新游戏机制
  * +可能的其他游戏机制改动
  * +可能的适配引擎版本更新
  * _不需要重新开档_
  * _可能存在游戏系统变化带来的存档转换_
  * _无法通过最小更新功能更新所有（引擎或res文件夹的）改动_
* 整数位（例：1.0/1.1/1.01/1.001→2.0）
  * 其间所有版本的改动内容
  * +大量新游戏内容
  * +可能的新游戏系统
  * +可能的游戏底层系统或基本运行逻辑改动
  * +可能的适配引擎版本重大更新（导致旧版本引擎无法运行游戏的更新）
  * _不需要重新开档_
  * _可能存在游戏系统变化带来的存档转换_
  * _无法通过最小更新功能更新_

> For developers:
> 
> 1.0开始的EraUma分支将按照以上版本号规则分为四类：
> * master分支：唯一的主分支/保护分支，负责发布。
> * dev分支：主开发分支，所有新增和改动内容必须先合并到dev分支，再由dev分支合并到master分支进入发布。
> * fix分支：bug修复分支，在master分支上直接分叉，bug确认后会先在fix分支上修复，再直接合并到master分支中。
> * 内容分支：由使用js的口上作者提交内容用，随用随开，不用即废。口上作者需要先将新口上或加笔提交到自己的分支（fork项目作者需要先提merge request将内容合并到EraUma仓库相应分支），然后通过dev分支在最终合并到master中。
>   * 例：特别周的spe分支，丸善斯基、醒目飞鹰的lines分支，待兼福来的kitaru分支，调教地文的train分支。
>   * 内容分支需要定期merge master分支以兼容最新的游戏机制和系统。

## Tutorial

EraUma发布采取分包制，即游戏本体包+游戏资源包拆分打包方式，使用时需要解压到同一个文件夹，才能通过[ERE引擎](https://gitgud.io/umaera/era-electron/-/releases/permalink/latest)启动

从ERE引擎顶部下拉菜单中【打开游戏文件夹】启动时，请确认打开的文件夹至少有以下结构：

* erauma文件夹
    * csv文件夹
        * Chara文件夹
        * _config.json
        * _fixed.json
        * 其他各种以csv为后缀名的文件
    * ere文件夹
        * data文件夹
        * event文件夹
        * page文件夹
        * system文件夹
        * utils文件夹
        * era-electron.js
        * main.js
    * （可选）res文件夹

如果文件夹不是以上结构，则无法顺利在ere引擎中打开运行
